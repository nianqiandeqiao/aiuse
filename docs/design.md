# 系统设计说明书

## 1. 项目简介

**AI 用药提醒与用药安全助手**面向居家养老场景，解决老年人"记不住吃药、吃错药、重复吃药"三类高频问题。

核心能力：

1. 老人档案管理（基础疾病、联系方式）
2. 用药计划管理（药品、剂量、饭前饭后、每日提醒时间点）
3. 服药打卡与按时率统计
4. **拍照识药**：拍药盒照片，自动识别药名并归一成标准药名
5. **用药安全提醒（核心创新点）**：自动检查老人当前全部用药之间的相互作用与重复用药，给出严重程度、机制说明和用药建议

## 2. 系统架构

系统采用前后端分离的典型三层架构：

```
┌──────────────────────────────────────────────┐
│  前端（Vue 3 + Vite，端口 5173）              │
│  老人档案页 / 用药计划页 / 打卡页 / 拍照识药页  │
└───────────────────┬──────────────────────────┘
                    │ HTTP + JSON（统一响应体 {code,message,data}）
┌───────────────────▼──────────────────────────┐
│  后端（Spring Boot 4 + MyBatis，端口 8081）   │
│                                              │
│  controller  接口层：参数接收、统一响应         │
│  service     业务层：校验、事务、规则计算       │
│  mapper      持久层：MyBatis 接口 + XML 映射    │
│  entity      实体层：与数据库表一一对应          │
└──────┬────────────────────┬──────────────────┘
       │                    │
┌──────▼──────┐      ┌──────▼──────────────┐
│  MySQL 9.6  │      │  百度智能云 OCR API  │
│  med_reminder│      │  通用文字识别        │
└─────────────┘      └─────────────────────┘
```

技术选型与理由：

| 层次 | 选型 | 理由 |
| --- | --- | --- |
| 后端框架 | Spring Boot 4.0.0（Java 17） | 主流企业级框架，课程已学，生态成熟 |
| 持久层 | MyBatis 3.5.19（`mybatis-spring-boot-starter` 4.0.0） | SQL 可控、便于教学与答辩讲解，官方已适配 Spring Boot 4 |
| 数据库 | MySQL 9.6 | 课程已学，本机已部署，支持事务与 utf8mb4 |
| 外部能力 | 百度智能云通用文字识别 | 中文药盒识别准确率高，有免费额度 |
| 前端 | Vue 3 + Vite | 组件化、上手快，适合 6 天冲刺 |

## 3. 模块设计

### 3.1 老人档案模块

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/api/elders` | POST | 新增老人 |
| `/api/elders` | GET | 列表，支持 `keyword` 模糊搜索（姓名/电话/基础病） |
| `/api/elders/{id}` | GET / PUT / DELETE | 详情 / 修改 / 逻辑删除 |

删除老人时**级联停用其全部用药计划**，避免打卡页出现"没有主人的药"。

### 3.2 用药计划模块

支持一个计划配置多个提醒时间点（`remindTimes` 形如 `08:00,20:00`），并支持按 `startDate`/`endDate` 限定生效区间、按 `status` 停用或恢复。

### 3.3 服药打卡模块

- 打卡唯一性：数据库对 `(plan_id, take_date, remind_time)` 建唯一索引，业务层再做一次前置判断，双重防重复
- 今日服药清单：把"进行中且在有效期内的计划 × 提醒时间点"展开成条目，并标注是否已打卡，前端打卡页直接渲染
- 按时率统计：`应服次数 = Σ(有效计划 × 区间内每天提醒点数)`，`按时率 = 已服 / 应服`

### 3.4 拍照识药模块

```
用户拍照 → 前端压缩 → POST /api/ocr/drug
   → BaiduOcrService：access_token（内存缓存 30 天）→ 调用 general_basic
   → 返回按行文本
   → DrugDictionary：把"阿司匹林肠溶片/拜阿司匹灵"等归一成"阿司匹林"
   → 返回 { rawText, lines, drugs[] }
```

药品词典独立成文件 `drug-dictionary.txt`（`标准名|别名(逗号分隔)|类别`），新增药品只需加一行，不需要改代码，便于后续扩充。

### 3.5 用药安全模块（核心创新点）

```
POST /api/interactions/check {elderId}
   → 读取该老人全部进行中计划
   → 药名归一（复用药品词典）
   → 检测一：重复用药（同一标准药名出现多次）
   → 检测二：两两组合匹配 interaction_rule 规则库
   → 按严重程度排序输出：机制说明 + 用药建议 + 依据来源
```

严重程度分三级：`1 严重`、`2 警告`、`3 注意`。规则库存在数据库表中，可随时扩展或停用某条规则。

## 4. 数据库设计

### 4.1 表关系

```
elder (老人档案)
  │ 1
  ├──────── n  medication_plan (用药计划)
  │                 │ 1
  │                 └──────── n  medication_log (服药打卡)
  │
interaction_rule (相互作用规则库，独立字典表)
```

### 4.2 表结构说明

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| `elder` | 老人档案 | `name`、`age`、`gender`、`phone`、`chronic_disease`、`note`、`deleted`（逻辑删除） |
| `medication_plan` | 用药计划 | `elder_id`、`drug_name`、`dosage`、`frequency`、`take_relation`（饭前/饭后/睡前）、`remind_times`、`start_date`、`end_date`、`status` |
| `medication_log` | 服药打卡 | `elder_id`、`plan_id`、`take_date`、`remind_time`、`take_time`、`status`（TAKEN/MISSED），唯一索引 `plan_id+take_date+remind_time` |
| `interaction_rule` | 相互作用规则库 | `drug_a`、`drug_b`、`severity`、`title`、`description`、`advice`、`source`、`enabled`，唯一索引 `drug_a+drug_b` |

字符集统一 `utf8mb4`，支持中文药名与 emoji；金额、时间等无关字段不冗余设计。

## 5. 关键流程

### 5.1 打卡流程

```
前端选择"老人 + 今日计划条目" → POST /api/checkins
  → 校验老人存在、计划存在且属于该老人
  → 校验该时间点未打卡（业务层 + 唯一索引双保险）
  → 写入 medication_log（记录实际服药时间）
  → 返回记录；前端刷新今日清单与按时率
```

### 5.2 交互流程（含语音播报）

前端在打卡成功后调用浏览器 `speechSynthesis` 播报"张三，阿司匹林已打卡"，无需额外后端接口，也不依赖外网。

### 5.3 异常处理

全局异常处理器把业务异常、参数校验失败、重复数据、未知异常统一转成 `{code,message,data}`，HTTP 状态码恒为 200，前端只判断 `code`，降低联调成本。

## 6. 创新点

1. **带依据的用药安全提醒**：不是简单的"红字警告"，每条冲突都给出机制说明、可执行建议和说明书来源，老人和家属看得懂。
2. **药品别名归一**：药盒上写的是"拜阿司匹灵""阿司匹林肠溶片"，系统统一归一到"阿司匹林"再检查冲突，解决 OCR 识别结果与规则库对不上的问题。
3. **重复用药检测**：除相互作用外，单独检测同一老人重复用药（现实中比相互作用更常见），规则库之外的第二道防线。
4. **适老化链路闭环**：拍照识药（不用打字）→ 今日清单（大字、按时段排好）→ 一键打卡 → 语音播报，降低老人使用门槛。

## 7. 安全与隐私

- 百度云密钥、数据库密码只写在 `application-local.yml`，该文件已被 `.gitignore` 忽略，仓库中只保留 `application-local.yml.example` 模板
- 老人档案不采集身份证号、医保卡号等敏感信息，仅保留用药必需的姓名、年龄、基础病、联系电话
- 规则库免责声明：仅用于课程演示与用药提醒，不能替代医生或药师的处方审核

## 8. 已知限制与后续工作

- 规则库目前 11 条，覆盖常见组合；后续可接入权威数据源扩充
- 未做登录鉴权，属于演示版；正式版需增加账号体系与家属-老人绑定关系
- 打卡提醒依赖前端页面打开，后续可增加微信/短信推送
