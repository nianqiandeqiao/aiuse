# 部署说明（局域网 / 公网 / 云服务器）

本系统的定位是**演示原型**：功能完整、测试完备，已具备**账号体系与数据隔离**（每个账号只能管理自己的老人与用药）。给真实老人使用前请先阅读最后一节。

## 方式一：本机演示（最简单）

双击 `启动系统.bat`，浏览器打开 <http://localhost:8081/> 即可。适合答辩现场、自己调试。

## 方式二：局域网访问（推荐给社区/学校内部试用）

同一 WiFi 下的手机、平板可以访问你电脑上的系统，不用买服务器、不用备案。

1. 双击 `启动系统.bat` 启动服务；
2. 查本机内网 IP：命令行执行 `ipconfig`，找"IPv4 地址"，例如 `192.168.5.223`；
3. 让同一个 WiFi 的人打开 `http://192.168.5.223:8081/`；
4. 如果别人打不开，多半是 Windows 防火墙拦了，第一次弹窗时勾选"专用网络"允许即可；也可以手动放行：

```powershell
New-NetFirewallRule -DisplayName "MedReminder 8081" -Direction Inbound -LocalPort 8081 -Protocol TCP -Action Allow
```

注意：本机演示模式**没有设访问口令**，只适合在信任的网络里用，不要把内网 IP 发到公开群里。

## 方式三：发布到公网给他人访问（今天就能用）

用 Cloudflare 免费临时隧道，把你电脑上的服务映射成一个公网 HTTPS 网址，无需注册、无需域名。

1. 双击 `启动公网访问.bat`；
2. 脚本会自动构建前端（如未构建）、下载 cloudflared、启动后端和隧道；
3. 窗口里会出现 `https://xxxx-xxxx.trycloudflare.com` 这样的地址，把它发给别人即可；
4. 别人打开后需要自己注册账号，登录后只能看到自己添加的老人与用药；
5. 关掉这个窗口 = 停止对外分享。

实测记录（2026-10-04）：公网访问首页返回 200；未登录访问 `/api/elders` 返回 401；登录后正常返回数据；账号之间数据互不可见（B 访问 A 的档案返回 404）。

限制：免费隧道地址是**随机且临时**的，每次重启都会变；**你的电脑必须一直开机**，关掉窗口服务就中断。适合答辩演示、给家人试看，不适合长期正式运营。

## 方式四：部署到云服务器（长期稳定）

需要一个公网服务器（阿里云/腾讯云轻量应用服务器即可，学生有优惠）。要点：

| 事项 | 做法 |
| --- | --- |
| 运行环境 | 服务器装 JDK 17 与 MySQL 9（或 8.0），把 `med-reminder-backend.jar` 传上去 |
| 数据库 | 建库 `med_reminder`，账号密码写进服务器的配置文件或用环境变量注入 |
| 敏感配置 | 用环境变量而不是文件：`APP_ACCESS_PASSWORD`、`SPRING_DATASOURCE_PASSWORD` |
| 启动方式 | `java -jar med-reminder-backend.jar`，建议配成 systemd 服务实现开机自启 |
| 反向代理 | Nginx 反代 8081，配 HTTPS 证书（Let's Encrypt 免费） |
| 域名备案 | 国内服务器绑域名必须 ICP 备案，通常 1~2 周；不绑域名只用 IP 访问可以不备案 |

Spring Boot 支持用环境变量覆盖配置，例如：

```bash
export SPRING_DATASOURCE_URL="jdbc:mysql://127.0.0.1:3306/med_reminder?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai"
export SPRING_DATASOURCE_USERNAME=medapp
export SPRING_DATASOURCE_PASSWORD=******
export APP_ACCESS_PASSWORD=******
java -jar med-reminder-backend.jar
```

## 上线前必须知道的风险

1. **权限粒度仍较粗**：已有账号体系与数据隔离（一人一份数据），但还没有"家属/护理员"角色区分、没有把同一个老人共享给多个家属、也没有操作审计日志。真实使用前建议补充角色权限与共享机制。
2. **个人信息合规**：老人健康与用药信息属于《个人信息保护法》中的**敏感个人信息**，公网服务需要告知同意、访问控制、加密存储与明确的责任人；课堂/比赛项目请**只使用虚构演示数据**。
3. **提醒能力有限**：当前的"提醒"依赖用户打开网页，真正给老人用需要接入微信服务号或短信推送。
4. **规则库未经专业审核**：11 条相互作用规则依据说明书整理，只能作为提示，不能替代医生或药师的处方审核。
5. **无监控无备份**：单机部署，数据库需要自己配定时备份，建议至少每天一次。

结论：**演示与内部试用可以直接用方式二或方式三；面向真实用户的正式服务，需要先完成"账号权限 + 合规 + 推送 + 药师审核"四件事。**
